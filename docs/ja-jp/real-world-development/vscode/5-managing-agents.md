GitHub Copilot をエージェント モードで使うと、コードベースを調べ、変更を提案し、ファイルを編集し、コマンドを実行します。VS Code の Copilot Chat では、ツールの呼び出しとファイルの編集をリアルタイムで確認できます。各差分をその場でレビューし、変更を個別に適用または取り消して、エディターを離れずに追加のプロンプトで会話を導けます。

この演習では、次の作業を行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視する。
- 提案されたファイル編集をレビューして適用する。
- ハイ コントラストに加えてライト モードを追加するよう、セッションの途中でエージェントに指示する。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中にデザイン チームから、既定のテーマが暗すぎると感じる利用者向けに、ライト モードの切り替えも追加してほしいという依頼がありました。新しい会話を最初から始めるのではなく、既存のセッションに追加の指示を出します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集など、各手順が表示されます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールして各ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナル コマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がチャット内に表示されます。
   - **Keep** を選択して変更を適用します。
   - **Undo** を選択して変更を取り消し、エージェントに再度変更を依頼します。
4. チャット上部の **Files changed** を開き、セッションで変更されたファイル全体を確認することもできます。

> [!NOTE]
> ツールの実行に許可が必要な場合 (たとえばターミナル コマンドの実行)、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可できるコマンドだけを承認してください。

5. エージェントがハイ コントラスト モードの実装を完了するまで待ちます。変更の概要を示す最終メッセージが表示されます。

## ライト モードを追加するようエージェントに指示する

ハイ コントラスト モードが完成したら、同じ会話にライト モードの切り替えを追加します。前の作業で変更したコンポーネント、スタイルの方針、local storage を使った設定保存の方法などのコンテキストがエージェントに引き継がれます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントが既存の変更を調べ、ライト モードの追加を提案する様子を確認します。
3. ハイ コントラスト モードのときと同じように、新しい編集をレビューします。各差分で **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合 (たとえば、好ましくない方法で切り替えユーザー インターフェイス (UI) をリファクタリングする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、追加の説明を送信します。

> [!TIP]
> 進行中のセッションに指示を加えると、最初からやり直すより効率的です。たとえば、「カスケーディング スタイル シート (CSS) を簡潔にして、セレクターの重複ではなく CSS 変数を使う」、「切り替えを 3 つに増やさず、既存の設定パネルにライト モードを追加する」、「両方の切り替えにキーボード ショートカットを追加する」といった調整や追加を依頼できます。

## 作業ファイルをレビューする

変更をコミットする前に、エージェントが編集したファイルを確認します。

1. VS Code の **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティックなハイパーテキスト マークアップ言語 (HTML)、local storage による設定の保持など、カスタム エージェントのアクセシビリティ パターンが反映されていることを確認します。
4. 内容に問題がなければ、Source Control パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードで進行中のセッションを監視して指示を加え、ファイル編集を確認して個別に適用または取り消し、コンテキストを保ったまま追加のプロンプトで作業範囲を広げました。

このレッスンでは、次の内容を確認しました。

- エージェントの作業をリアルタイムで監視する。
- ファイル編集を個別に適用または取り消す。
- 追加のプロンプトでセッションの途中に指示を加える。

次はアクセシビリティ機能をプルリクエストとして公開し、このラボでローカルのカスタム エージェントが作成した変更をレビューします。
