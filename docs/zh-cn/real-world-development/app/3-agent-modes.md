我们先为项目添加了一项小功能，但更复杂的更改需要更完善的流程。GitHub Copilot app 支持组织现有的工作流程，帮助我们用正确的方法构建所需功能。从本课开始，你将通过几节课遵循典型的智能体驱动开发流程：先使用议题生成新功能，确认代码有效且功能行为符合预期，最终将更改成功合并到项目中。

> [!NOTE]
> 后续功能工作流将沿用同一个会话。通常，不同类型的文件会使用不同会话或 PR；这里为聚焦核心概念而简化了流程。

在本课中，你将：

- 从 GitHub 议题启动新的智能体会话。
- 在 **Plan** 模式中明确需求。
- 使用 **Autopilot** 模式实现新功能。
- 审查代码。
- 在浏览器画布中手动验证功能。

继续完成该功能时，你将更新存储库说明、自定义现有的 quality-checks 技能、添加模型上下文协议（MCP）验证、创建质量保证（QA）智能体并打开功能拉取请求（PR）。

## 场景

Tailspin Toys 的游戏目录不断扩大，访客需要按类别和发行商缩小游戏范围。待办议题描述了功能，但多个类别如何组合等细节需要在编码前达成共识。你将使用 Plan 模式确定这些决策，然后授权 Autopilot 在明确范围内实现功能。

## 背景

将人工智能（AI）编码智能体引入开发流程不会改变基本原则。事实上，这些原则反而更加重要。大多数开发人员遵循类似以下的流程：

1. 打开已创建的议题，查看需要完成的工作详情。
2. 为需要构建的内容制定计划。
3. 构建并审查代码。
4. 运行测试以验证代码。
5. 手动验证新功能。
6. 创建拉取请求（PR）。
7. 代码通过审查且持续集成（CI）流程成功后，合并代码。

> [!NOTE]
> 具体流程会因团队和组织而异，但大多数流程都是以上步骤的变体。

遵循这种标准方法，可以确保 AI 生成的代码满足既定要求，并经过与手写代码相同的审查流程。

## 会话模式

**会话模式**控制智能体的自主程度。可以从提示字段下方的下拉菜单中设置模式，并随时更改：

- **Interactive**：你与智能体协同工作。智能体提出更改建议，并等待输入后再继续。
- **Plan**：智能体先创建计划。你审查并批准计划后，智能体才会执行。
- **Autopilot**：智能体完全自主工作，包括编写代码、运行测试和迭代，无需等待输入。

先在 Plan 模式中审查计划，再使用 Autopilot 实现。

## 从议题启动会话

开始前，确认星级评分 PR 已合并，并且本地 `main` 已更新。接下来从已有的筛选议题启动会话，无需另建议题。

1. 在侧边栏 **Sessions** 下选择 Tailspin Toys 存储库文件夹，然后在存储库顶部导航中选择 **Issues**。打开 **Allow users to filter games by category and publisher**。
2. 选择 **New session**，并选择基于已更新 `main` 的 **new working tree**。

   ![GitHub Copilot app 的议题视图，箭头指向 New session 按钮](../../../_images/app-new-session-from-issue.png)

3. 确认议题已附加到会话，并在模式选择器中选择 **Plan**。

> [!NOTE]
> 如果找不到 Node.js 或 npm，请让智能体运行 `node --version` 和 `npm --version`。如果这些命令在终端中可用，但会话中不可用，请检查应用的 PATH 或版本管理器设置，然后完全退出并重新打开应用。重试失败的操作和检查；不要仅仅因为智能体找不到 npm 就重新安装它。

## 规划筛选功能

规划让你能在 Copilot 编写代码前审查方案。由于会话从议题启动，Copilot 已获得功能请求的上下文。

1. 发送以下提示：

    ```plaintext
    Build this feature.
    ```

2. 回答 Copilot 的问题，并对照议题验收标准审查计划。确认计划涵盖类别和发行商筛选、无障碍控件、数据访问更改和测试。
3. 讨论尚不明确的行为，例如多个类别如何组合，或没有匹配游戏时如何处理。

4. 确认计划使用项目现有工具执行 lint、单元测试、端到端（E2E）测试和类型检查，并将范围限定为筛选功能的实现和测试；完成质量工作流后再创建 PR。
5. 批准前先要求修改不合适的计划，并保留议题的统一资源定位符（URL）和已达成共识的说明，供后续验证使用。

## 明确批准 Autopilot

对计划满意后，批准 Autopilot 执行计划，并确认当前模式。Copilot 随后会按既定计划实现功能、生成代码并运行测试。

1. 选择 **Approve and implement this plan**，或当前版本中的等效选项。
2. 不要假定批准后模式会自动切换；确认活动模式指示器显示 **Autopilot**。

> [!NOTE]
> 批准后可能立即开始实现，因此应先审查计划。如果 Copilot 报告缺少依赖项或端口冲突，请先解决环境问题，再将检查视为已完成。只停止自己启动的服务器。

## 审查并验证实现

生成代码后，与合并其他代码一样，先审查实现并检查验证结果。

1. 打开 **Changes**，检查筛选功能的实现和测试。
2. 对照议题和已批准的说明检查结果，包括多个类别和发行商的组合。确认更改遵循现有存储库说明。
3. 查看 lint、单元测试、E2E 测试和类型检查的输出。跳过的检查不能算通过。
4. 接受实现前，解决失败项并重新运行受影响的检查。Playwright 的 E2E 配置会构建并提供预览服务，且可能复用本地服务器；确保被测服务器属于此工作树，而不是之前课程的服务器。

## 体验新功能

代码看起来没有问题，但能否正常运行？像之前一样启动应用，并在浏览器画布中打开网站。

1. 使用以下提示，请 Copilot 启动应用并在浏览器画布中打开页面：

   ```plaintext
   Start the app and open it in the browser canvas.
   ```

2. 等待应用启动，Copilot app 内会打开浏览器窗口。
3. 选择一个类别，确认结果符合该类别。清除筛选，再选择一个发行商，确认结果符合该发行商。
4. 同时应用类别和发行商筛选，并根据议题和已批准的计划检查结果。如果支持多个类别，请验证已约定的组合行为。
5. 测试一个没有匹配游戏的组合，检查空状态。清除或重置筛选，确认完整列表重新显示。
6. 检查完毕后，使用以下提示，请 Copilot 停止为此会话启动的开发服务器并关闭浏览器画布：

   ```plaintext
   Stop the dev server and close the browser canvas.
   ```

## 为后续课程保留此会话

筛选功能 PR 将在后续工作完成后创建。现在应保留会话、工作树和分支，以便接着应用自定义说明并添加技能和 QA 改进。

1. 不要创建或合并筛选功能 PR。将此会话、工作树和分支保留到后续工作中；停止开发服务器后，可以让会话暂时空闲。

## 总结和后续步骤

你已使用不同的智能体模式构建并审查功能。在本课中，你：

- 从 GitHub 议题启动了新的智能体会话。
- 在 **Plan** 模式中明确了需求。
- 使用 **Autopilot** 模式实现了新功能。
- 审查了代码。
- 在浏览器画布中手动验证了功能。
